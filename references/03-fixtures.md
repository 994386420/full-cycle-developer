# 阶段 3：建立验收场景

在任务目录写本地场景清单，例如 `evidence/ui-cases.md`。每个 UI 任务/验收条件指向具体标题，包含：

- 设计来源、快照版本、状态名称和截图区域。
- 入口、前置数据、复现步骤、隐藏/禁用/选中/展开等状态及其断言。
- 视口、缩放、DPR、文字缩放、主题、语言、安全区和字体。
- 客观预期、截图/数值测量方法，以及已有功能当前偏差。

老功能先取得当前实现基线。新功能可以先建场景、后补实际截图；不能伪造截图或虚构真实服务数据。不得为了制造截图而在生产环境创建业务单据。

把每条 UI 任务的 `fixture.status` 标为 `ready`，`fixture.path` 指向清单文件及标题。无设计稿、非 UI 任务等使用 `not_applicable` 并填理由；无设计稿仍须验交互和数据。

如用户已授权线上测试文档，可使用线上文档，但保留本地映射，且不能仅靠无权限访问的外链充当本地验收证据。

Gate：场景与任务一一对应，可复现，设计状态已覆盖。通过后才进入业务实现。
