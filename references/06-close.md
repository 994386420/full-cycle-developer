# 阶段 6：双向盘点、清理与交付

1. 对照 `git diff`、调用点和运行结果逐项盘点：清单说做完的代码是否真的存在；代码已经改完的项目是否还挂着未做；是否有超出来源的改动或漏掉的入口。
2. 将双向盘点写入任务目录文件，把路径填到 `reconciliation`。不要把初始用户改动纳入本次完成量。
3. 每个剩余项明确处理：继续完成、交接待验，或按明确授权延期/放弃。`handoff` 必须对应任务及条件，写清责任归属、阻塞原因、下一步；延期/放弃写明授权依据。
4. 清理自己创建且已无用的临时页面/进程/文件，保留 Plan、原始证据、差异清单和复验记录。不要关闭用户既有会话，不删除未确认归属的文件。
5. 填写 `cleanup.reviewed`、`cleanup.note`；运行 `gate --stage 6` 并更新 `PLAN.md`。

最终汇报以任务账本和实际证据为准：完成 M/N 项，分别说明静态检查、测试、构建、真实服务和设备的验证情况，列出未完成事项与知识更新入口。`partial` 不得表述成“全部完成”或“全流程验收通过”。

Gate 不是发布批准，也不触发 Git 提交、推送、合并或部署；这些操作继续遵循当前任务授权与项目规则。
