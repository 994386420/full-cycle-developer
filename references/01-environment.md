# 阶段 1：环境检查

读取项目规则、相关历史记录、实际依赖和启动配置。记录 Git 分支、HEAD 和已有修改；确认当前工作目录正确，不覆盖其他任务。

```bash
python3 "$SKILL_DIR/scripts/workflow.py" preflight --root "$PROJECT_ROOT" --task-dir "$TASK_DIR"
```

需要运行设备或代理时，显式追加 `--device <设备ID>`、`--port 127.0.0.1:8899` 等实际条件。脚本只检查指定项，不假定所有项目都需要 whistle 或固定端口。

脚本检查 Git、对应技术栈工具、Flutter 包解析文件以及 `.fvmrc` 与实际 SDK 的一致性。版本、设备和端口检查结果写入 `evidence/preflight.json`。版本冲突或缺少依赖时只修相关项，不擅自升级 SDK、依赖或系统配置。

自动检查未覆盖的必需条件，例如登录态、代理规则、接口权限、当前页面是否运行本地改动，补入报告的 `manual_checks`。每条含 `name`、`ok` 和 `detail`；不能用“端口通了”代替“当前运行的是本地代码”。使用真实可见的改动、构建版本或调试标识核实。

本次仅文档/脚本工作时可选 `generic`，但不能用它绕过实际 Flutter 开发所需的工具检查。没有模拟器或真机时，先明确哪些验收方法受影响，不把缺少设备当成已验证。

Gate：必需检查通过后进入 Plan；失败则列出实际阻塞原因，继续不依赖阻塞项的只读分析。
