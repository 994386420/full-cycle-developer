# Flutter 适配

## 实际工程优先

从 `pubspec.yaml`、锁文件、`.fvmrc`、IDE 启动配置和项目规则确认 SDK、flavor、入口、平台和状态管理。不要把示例项目的 Provider/MVVM 等约定强推到其他项目。先查现有主题、组件、路由、模型、枚举和网络层。

`flutter pub get` 用于确实需要的依赖解析，不能无理由更新整个依赖树。序列化只在相关模型改动时按既有生成流程处理，不手改无关生成文件。

## 设计与视觉

蓝湖：先发现当前可用 MCP 工具，再获取设计列表/ID → 不可变设计总览 → 局部区域检查/切图。需求与视觉稿分别读取，记录版本；不能把生成 HTML/CSS 的参考当作 Flutter 实测结果。Figma 使用官方 Figma MCP。

记录逻辑尺寸、实际像素和 DPR，区分设计基准宽度与 ScreenUtil 等缩放结果；同时检查安全区、键盘、大字体、溢出、空态、错误态、加载态、禁用态和隐藏态。

浏览器里的原型、HTML 模拟和 Flutter Web 截图不证明 Android/iOS 原生效果。Widget/golden 证据也仅证明受控环境内的布局和行为。

## 验证层次

| 层次 | 常用方式 | 能支持的结论 |
| --- | --- | --- |
| 静态 | `flutter analyze <相关路径>`，必要时全量 | 当前范围诊断，不证明交互或业务结果 |
| 单元/Widget | `flutter test <相关测试>` | 受控断言、状态和逻辑 |
| Golden | 既有基准测试与差异图 | 指定字体、DPR、文字缩放下的离屏结果 |
| 构建 | 实际目标 flavor/入口的 build | 编译和产物生成，不证明安装/启动/服务可用 |
| 模拟器 | 启动、操作、截图、重开 | 该模拟器环境中的应用行为 |
| 真实服务 | 授权测试账号和接口链路 | 该服务环境与样本的联调结论 |
| 真机 | 实际 Android/iOS 操作与截图 | 指定设备/系统下的行为，不能泛化全机型 |

对 Provider、导航、请求并发、切店/切账号、返回刷新和持久化改动，优先验证真实调用链和时序。接口路径集中维护，字典状态复用枚举/extension；具体以项目规范为准。
