# 阶段 5：沉淀经验

回顾需求理解、环境、实现、验证和返工。只写当前源码、日志、截图或复现步骤支持的结论。

- 一次迭代的事实、联调状态、验证与待办：更新当前迭代记录。
- 长期业务契约、跨模块约束、必须遵守的规则：更新对应规则文档。
- 可复用的操作方法和已核实的反直觉经验：先读已有相关 skill，在原位置补充；确实形成独立能力时再新建 skill。
- 无可复用结论：`learnings` 写 `kind: none` 并说明各环节为什么无需新增知识，不能只填“无”。

每条非 `none` 的沉淀记录 `summary`、实际更新文件 `path` 和依据 `evidence`（任务目录内文件路径）。维护项目的文档导航和知识索引。

不要把尚未跑过的工作流能力、未联调的接口或尚未验收的设备写成已验证事实。临时调试模式不省略对是否需要沉淀的判断。

Gate：知识变更有依据、没有重复入口和未经验证的“经验”。
